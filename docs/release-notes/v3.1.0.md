# v3.1.0 — the remaining ten debts (D-18…D-27) are paid off

Every change in this line is an **assertion / observability** change: no fastboot or VCOM command,
argv shape, timing or retry was touched, and no device was contacted during development
(the `fastboot` used by tests is a stub).

Verification: `dotnet build Kirin-Tool.csproj` = 0 errors, `dotnet build KirinTool.Cli/KirinTool.Cli.csproj`
= 0 errors, `tests/suites.txt` = **34/34 suites rc=0** (six new harnesses: `CommandOutcomes`,
`KnowledgeDedup`, `SocWriteRequirements`, `ModemLinePolicy`, `LoaderDirectory`, `LoaderPackaging`).

Still open after this release: **no `D-` item**. What remains in `docs/debt-register.md` is the platform-assumption
group (`P14` bundled fastboot needs a network build, `P01` Windows port-name parsing, `P05`/`P06` tty/interface

data, the `OemInfoService` 0600 / unlockcode handling is code-reviewed but not independently asserted).

`tests/StableParity/boundary.json`: the `Services/FirmwareUnlocker.cs`, `Services/VcomFlasher.cs` and
`MainWindow.axaml.cs` hashes were recomputed on the merged tree, each with the behaviour-change reason in its
`reference` field. `D-23`(d) "an over-long path is only a warning" was intentionally left as a warning:
turning it into a refusal changes what the GUI lets the user attempt, which is a maintainer decision.

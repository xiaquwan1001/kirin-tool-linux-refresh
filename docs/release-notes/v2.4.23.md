Fork build of Kirin Tool for Linux 2.4.23 (downstream of Redminote11tech/kirin-tool-linux).

One-line: the third audit round's three highs are closed — an UPDATE.APP entry name can no longer
write outside the extraction directory, the MCP approval socket can no longer be answered by another
local user, and the GUI's "Convert OEM" direct branch now asks for the same approval ticket and
write-identity check as every other oeminfo write. Five medium parser/temp-file bounds landed with it.

Why (docs/audit/2026-11-15/round3.md, read-only audit of 21 findings)
1. **[high] UPDATE.APP partition name → path traversal.** `USBUpdateApp` took the 32 header bytes and
   concatenated them into `Path.Combine(directory, name + ".img")` with `FileMode.Create` and no check,
   while the strict parser in `Utils/UpdateApp` had a whitelist all along. An entry named
   `../../.config/autostart/x` wrote outside the dload directory.
2. **[high] approval socket could be forged.** With no `XDG_RUNTIME_DIR`, the bridge fell back to a
   world-writable `/tmp` path and accepted any client's answer, so a local user could approve any
   `confirm:true` write (redline included). `TypedConfirm` from the peer was trusted as-is.
3. **[high] GUI "Convert OEM" bypassed both gates.** Three `OemCommandAsync` calls
   (`oeminfoerase-disablewp`, `oeminfowrite-KTModel@…`, `-KTVendor@…`) ran with no approval ticket and
   no identity check — the same irreversible-oeminfo shape as the 2026-11-15 incident.

What changed
- **S1** new `Utils/PartitionNames.cs` is the single whitelist shared by both parsers (ASCII letters,
  digits, `_`, `-`, `.`; never `.`/`..`; length capped), and `ChildPathWithin` re-checks the resolved
  path against the target directory, so a name cannot escape even if a separator slips through. Header,
  image and unlock-code writes are `CreateNew` + 0600. Also: `startAddr` widened to `long` and header
  length bounded (the old int truncation turned >2GiB offsets negative).
- **S2** approval IPC moved to a private per-uid 0700 directory (no `/tmp` fallback, world-readable
  `XDG_RUNTIME_DIR` rejected), socket 0600, server verifies the peer uid via `SO_PEERCRED` with a 30 s
  read timeout and bounded concurrency, the client verifies the server the same way, and anything that
  cannot prove identity **fails closed**. The confirmation phrase is compared literally against
  `Approved.TypedPhrase` (peer-supplied `TypedConfirm` is no longer trusted), and redline approvals are
  not cached per session.
- **S3** the Convert OEM branch now takes an `oeminfo-flash` approval ticket and calls
  `DeviceWriteOps.OemInfoEraseWriteProtectionAsync` / `OemInfoWriteFieldAsync`, which run the write-
  identity gate; the ticket is compiler-enforced. Progress text, command order and OKAY classification
  are unchanged. `XloaderPatcher`'s direct write was reviewed and has a single gated entry point.
- **M1** secrets and staging use `Utils/PrivateWorkDirectory` (random 0700 dir, 0600 files) instead of
  predictable `/tmp/kirin-tool-dload`; **M2** `SuperMerger` validates header/chunk geometry and uses
  `checked` arithmetic so a corrupt super image throws instead of being flashed; **M3** `OemInfoEditor`
  bounds the length prefix, payload and padding (model/vendor ≤ 64, no control characters); **M4** gzip
  decompression is capped at `min(free space, max(512 MiB, 32×compressed))`; **M5** flashing XML uses
  `DtdProcessing.Prohibit`, `XmlResolver = null`, a 16 MiB document cap, and image paths confined to
  the XML's directory subtree.

Verification (no hardware touched)
- `dotnet build -c Debug`: 0 errors; CLI `-c Release`: 0 errors.
- `tests/suites.txt`: 25/25 harnesses exit 0. WriteGates 114 → 141, Kirin9000 52 → 60,
  ApprovalGate 62 → 111, UsbTransport 8 → 25, StableParity 35 (four frozen hashes refreshed; merged
  sparse-image golden bytes unchanged), SurfaceParity 415, OpLogging 163, McpProtocol 17.
- New assertions: a forged `../../evil` UPDATE.APP writes nothing inside or outside the directory; a
  peer with a different uid is refused; the Convert OEM branch refuses without a ticket.

Known gaps
- `sum(TotalBlocks)` cross-check in SuperMerger was deliberately skipped: DONT_CARE chunks carry no
  block count, so the check would reject valid images (and break the golden-byte test).
- Reads of the identity probe still pass when the probe cannot run at all (no device / stub / timeout);
  only a nonsense `product` answer refuses.

Fork build of Kirin Tool for Linux 2.4.24 (downstream of Redminote11tech/kirin-tool-linux).

One-line: a hotfix for 2.4.23's CI failure — the approval server no longer chmods a directory it did
not create, so an operator- or test-supplied socket path under `/tmp` binds again, while the 0600
socket and the kernel-reported peer uid remain the actual gate.

Why: 2.4.23 made the approval channel verify the peer uid, and gave the socket directory a private
0700 mode. The server applied that mode unconditionally, including to a pre-existing parent such as
`/tmp` (root-owned, 1777), where the chmod fails with EPERM and the bind is abandoned. The local
suite passed only because its temp directory is user-owned; CI runs with `TMPDIR` unset, so
`tests/ApprovalGate` could not bind and `cli-mcp-ci` failed (exit 134).

What changed
- `GuiApprovalServer.Start()` only creates **and** tightens a directory it created itself. An
  existing parent is left untouched (chmod on someone else's directory cannot work, and tightening a
  shared temp directory to 0700 would break every other user). The socket entry is still created
  0600, the peer uid is still verified on both ends, and an unverifiable peer is still refused.
- No other behaviour changed: same request/answer protocol, same fail-closed rules, same
  `TypedPhrase` comparison.

Verification (no hardware touched)
- `dotnet build -c Debug`: 0 errors; CLI `-c Release`: 0 errors.
- Full `tests/suites.txt` re-run **under CI conditions** (`TMPDIR=/tmp`, `XDG_RUNTIME_DIR`
  unset): 25/25 exit 0 (WriteGates 141, Kirin9000 60, ApprovalGate 111, UsbTransport 25,
  StableParity 35, SurfaceParity 415, OpLogging 163, McpProtocol 17).
- `tests/ApprovalGate` alone reproduces the CI failure before the fix and passes after it.

Known gaps (unchanged from 2.4.23)
- `sum(TotalBlocks)` cross-check in SuperMerger is still skipped deliberately (DONT_CARE chunks
  carry no block count).

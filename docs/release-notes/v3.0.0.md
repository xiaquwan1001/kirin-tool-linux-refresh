# v3.0.0 — the security-audit line closes (2026-11-17)

Major version because the three audit rounds of 2026-11-15 (round3/round4/round5) plus the r6/r7
debt batches change what the tool is *allowed to claim*: every write and every read now carries a
judged verdict, the approval channel is authenticated by the kernel, untrusted package input is
bounded, and the GUI can no longer take a direct write path around the gates. Wire commands,
frame layouts, timings and retries are unchanged everywhere; the frozen files that did change are
listed with the reason in `tests/StableParity/boundary.json`.

Evidence for this release was re-derived, not taken from the lane reports:
`dotnet build Kirin-Tool.csproj -c Release` and `KirinTool.Cli.csproj -c Release` = 0 errors,
`tests/suites.txt` = **28/28 suites rc=0** (WriteGates 209, SurfaceParity 430, OpLogging 168,
Kirin9000 125, ApprovalGate 114, VcomUnlockCli 98, VerdictHonesty 81, LogMerge 79, PwnJumpTable 53,
UsbUpdateVerdict 39, DloadSentinel 38, StableParity 35 …), plus the CI smoke steps re-run by hand
(`--help`, `version`, stubbed `doctor` = `ok:false`/`status:degraded-fastboot-parity`/exit 6, stdio
MCP `initialize`+`tools/list` exposing `flash_ota`).

Approval channel (round5 S2)

  **both** ends and fail-closed (`Services/Approval/PeerCredentials.cs`, `GuiApprovalBridge.cs`).
- A peer-supplied `TypedConfirm: true` is no longer evidence: the redline phrase is compared

## Still open (documented, not claimed fixed)

`docs/debt-register.md` §2 keeps the full list with reasons. As of 3.0.0:

- **D-18** VCOM RTS/DTR decision by driver name (`option`) instead of capability probing.
- **D-19** loader directory naming/`KIRIN_LOADERS_DIR`.
- **D-20** `packaging/publish.sh` still does not produce `loaders/` for the deb/AppRun.
- **D-21** MCP `protocolVersion` is fixed at `2024-11-05`.
- **D-22** two udev rule wordings; static text check cannot see `uaccess` limits.
- **D-23** GUI implicit steps (always-on pre-op backup, single-line results, blocking redline re-confirm).
- **D-24** `FrpBypassResult`/`EnableDowngradeResult` OR-semantics (dead code today).
- **D-25** failure vs unsupported vs timeout still not fully separated in five read paths.
- **D-26** four copies of the "needs a replug / write protection" SoC lists.
- **D-27** duplicated knowledge (OEM_INFO version probe, UPDATE.APP alias table, magic scan).
- Known trade-offs: M5 refuses absolute `<image>` paths outside the package subtree (fail-closed);
  R3's Windows PnP grouping is asserted on fake enumeration data only (no Windows host here);
  `OemInfoService`'s 0600 on the pulled temp image and the upper-directory unlockcode copy are
  code-reviewed but not separately asserted.

## Upgrading

No CLI/MCP contract was removed. New JSON keys (all additive): `degraded`, `fastbootFallback`,
`status`, `battery`/`battery-unknown` gate values, `device-identity`/`device-identity-read`
verdicts, `sparse-block-sum`. Exit code 6 is new (`info`/`doctor`: connected but nothing readable).

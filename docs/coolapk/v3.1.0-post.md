## 正文

在 Linux 上刷华为/麒麟手机，我们把自己维护的那条线（Kirin Tool for Linux · refresh）跟原版之间的差别整理了一版，顺手发上来。

先说结论：**refresh 不是原版的中文皮肤，是把「敢不敢真写设备」这件事重新做了一遍。**

## 相对原版，主要改了这几块

**1. 一个实现，三张面孔**
原版只有图形界面。现在 GUI、命令行、MCP server 共用同一套逻辑（同一个 CliRunner）。命令行能做的事，界面也能做，反之亦然，不存在「只有点界面才能解锁」这种分叉。

**2. 写设备的判定改成机器可读**
每个写命令都回一个 gate：plan-only / refused / confirmed / applied / partial。客户端不该靠猜退出码——退出码 4 过去同时表示「没确认」和「被拒绝」，现在各说各的。
更关键的一条：**成功 = 进程退出 0 且设备回 OKAY**。原版有一次「设备拒绝了写入，界面显示刷写完成」，就是因为只看退出码。现在设备说「already fastboot unlocked」会被记成**没写入**，不会骗你。

**3. 红线分区真的红**
oeminfo、nvme、persist、modem_secure、modemnvm*、certification 这些碰了基本不可逆。默认拒绝，必须手动覆盖；而且**覆盖参数只在命令行存在**，MCP 层直接拒（AI 客户端没法给自己授权）。SN 重写、FRP 清除必须弹窗给你看「旧值 → 新值」。

**4. 每次真写之前先备份**
计划里的红线分区 + ptable，dump 到带时间戳的目录，附 manifest.json（每个分区的大小、SHA256、成功/不支持/失败）。备份是尽力而为不是闸门——因为临时 loader 常常不支持 dump，设成硬闸门等于把唯一能走通的路堵死。

**5. 自己的发布流水线**
原版的 release 在 Linux 上基本装不上：ICU soname 每个发行版都变，24.04 之后 libssl3 变成 libssl3t64，dpkg alternatives 不支持通配。现在一个提交同时产出 deb / AppImage / tar.gz / 单文件 CLI，deb 依赖在三个 Ubuntu 代上跑 apt-get -s 模拟验证，AppImage 卡在 glibc 2.31（Ubuntu 20.04 能跑）。

**6. 双 CI + 测试单一事实源**
tests/suites.txt 一份清单，GitHub Actions 和 GitLab CI 都跑同一批（目前 34 套免硬件 harness）。只有一条流水线跑的测试，注定会烂。

**7. 安全审计线（v3.0）与判定诚实化（v3.1）**
读和写都有身份闸门、每条派生命令带 -s 串号、审批通道两端做内核级认证、不可信包输入白名单/限域/限长。v3.1 又把「超时/不支持/失败」从塌缩成 null 改成各自带种类（probe-timeout 不会被说成「没有设备」），MCP 也会协商协议版本了。

## 顺手的地方
· 记住上次选的芯片型号、固件和目录，浅色/深色主题
· flash-ota 可以先只出计划（一个字节都不写），看清再上
· 电量不足提示一句（只提示不拦人，但还是建议 50% 以上）
· 每次 VCOM 操作都留帧级日志，失败能事后对账

## 提醒
刷机有风险，数据会没，型号/固件不对会直接黑砖。完整 Full-OTA 流程我们只在华为 P40 Pro（ELS-AN00，麒麟 990 5G）上跑通过一次端到端：46/46 分区 OKAY，重启 22 秒进系统。
